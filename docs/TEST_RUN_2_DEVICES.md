# سناریونامه تست عملی دو دستگاه — موج آنلاین (فاز ۴۷)

> هدف: اجرای واقعی روی دو دستگاه روی یک LAN و ثبت یافته‌ها/KIها.
> بیلد مبنای تست: 0.27.0 (releases) یا بیلد تازه‌تر 0.28.0 پس از فاز ۴۸.
> هر سناریو: گام‌ها → نتیجه مورد انتظار → ☐ چک‌باکس. یافته‌ها را در جدول انتهای سند ثبت کنید.

## ۰. آماده‌سازی (هر دو دستگاه)

- ☐ نصب بیلد روی هر دو دستگاه؛ اتصال هر دو به یک شبکه LAN (یا همان رuter).
- ☐ فایروال ویندوز: پورت بازی (پیش‌فرض 51987) برای TCP ورودی باز باشد؛ در اولین اجرا پرس و تای ویندوز → Allow.
- ☐ دستگاه A = **هاست**، دستگاه B = **کلاینت**. در لابی هاست «host» را می‌زند، کد/IP را می‌گیرد؛ کلاینت همان را join می‌کند.
- ☐ پس از اتصال: بنر نام هم‌بازی در لابی دیده شود (P1/P2 با نام‌های واقعی).
- ☐ تیزر لابی: انتخاب type-pong در پیکر بازی → متن «the first real versus — one shared ball state-synced 20 times a second» دیده شود.

## ۱. الگوی R — مسابقه seeded تا هدف (Sky Climber و Runner)

**Climber:**
1. ☐ هاست بازی را start می‌کند → هر دو هم‌زمان وارد صفحه بازی می‌شوند (بدون فاصله محسوس).
2. ☐ سکوهای هر دو دستگاه یکی هستند (جفت‌ها را مقایسه کنید — ترتیب و کلمه‌ها).
3. ☐ یکی به ارتفاع هدف (۳۰) می‌رسد → اورلی «awaiting» برای او تا دیگری تمام کند؛ سپس داوری (برنده/بازنده/تساوی دقیق).
4. ☐ rematch → همان سکوهای قبلی (seed همان)، state صفر.
5. ☐ وسط صعود دستگاه B خارج می‌شود (X بسته شود) → دستگاه A پیام void و خروج به منو؛ هیچ رکوردی ثبت نشده.

**Runner:** همان گام‌ها با خط پایان ۴۰۰م؛ ☐ سه‌جان در HUD حریف هم زنده آپدیت می‌شود.

## ۲. الگوی S — امتیاز-مسابقه (سه چهره)

**Wordle (بدون هورن — پایان با هر دو):**
1. ☐ شروع → جواب هر دو دستگاه یکی است (حدس اول را هر دو یکسان بزنید — رنگ‌ها یکی).
2. ☐ progress زنده: تعداد حدس حریف در پنل بالا-راست آپدیت می‌شود.
3. ☐ یکی حل می‌کند → «your guesses are locked — waiting for …»؛ دیگری که حل کند یا تمام کند → داوری (حدس کمتر برنده، زمان tiebreak).
4. ☐ آمار روزانه wordle هر دو دستگاه دست‌نخورده (مسابقه آنلاین نباید در آمار محلی بنویسد).

**Type Snake (مسابقه مرگ):**
1. ☐ استریم غذایی هر دو یکی (کلمه و جای غذا).
2. ☐ یکی boxed-in → awaiting → دیگری هر وقت مرد داوری (امتیاز بالاتر، بقای بیشتر).
3. ☐ آمار snake محلی دست‌نخورده.

**Letter Strike / Lane Defense (مرگ با جان/دیوار):** همان الگوی snake؛ ☐ پنل حریف (جان/دیوار) زنده.

**Fruit Slash / Firefight / Beat Keys / Crane (هورن/پنجره):**
1. ☐ پنجره مشترک هر دو هم‌زمان می‌بندد (هورن در fruit-slash/crane، پنجره بقای firefight، آخرین نوت چارت beat-keys).
2. ☐ beat-keys: چارت هر دو یکی؛ acc/امتیاز حریف زنده؛ **تب‌سوییچ وسط چارت → abandon → حریف وقتی چارتش تمام شود می‌برد**.
3. ☐ داوری امتیاز بالاتر؛ تساوی دقیق → draw.

**Stack Attack / Balloon Pop / Pair Keys / Nitro Run:** ☐ هر کدام یک راند کامل + داوری درست طبق قاعده سند.

## ۳. الگوی H — bot-duel (لیست کلمات هاست)

1. ☐ هاست طول مسابقه (quick/standard/long) انتخاب می‌کند → کلاینت همان تعداد کلمه می‌بیند.
2. ☐ شمارش ۳-۲-۱ هم‌زمان → دویل؛ progress پیس‌ساز حریف زنده.
3. ☐ پایان: برنده/بازنده + rematch (همان کلمات).

## ۴. الگوی V — type-pong (اولین versus واقعی)

1. ☐ هاست می‌سازد؛ کلاینت وارد می‌شود؛ توپ هر دو از یک نقطه شروع می‌شود.
2. ☐ حرکت روان کلاینت: توپ با interpolation بدون پرش محسوس (snapshotها 20/s)؛ بین snapshotها پیش‌بینی محلی کوتاه.
3. ☐ پدال حریف در هر دو سمت درست رندر می‌شود (بالا=حریف، پایین=خودت) و فقط با تایپ حرکت می‌کند.
4. ☐ تایپ کلمه → snap روی توپ؛ برخورد/امتیاز در هر دو یک لحظه ثبت می‌شود.
5. ☐ بازی تا ۵ → صفحه داوری از پرسپکتیو هر دو درست («you win!» فقط برای برنده) + best rally.
6. ☐ rematch → کلاینت درخواست، هاست همان start را دوباره می‌فرستد، هر دو ریست.
7. ☐ خروج هاست وسط بازی → کلاینت پیام void و بازگشت به منو.

## ۵. سناریوهای لبه (سراسری)

- ☐ قطع شبکه وسط مسابقه (وای‌فای هر دو را قطع/وصل) → پیام void در هر دو؛ بازگشت به منو؛ هیچ رکورد.
- ☐ خروج با دکمه back وسط مسابقه در سه بازی مختلف → حریف پیام می‌گیرد و state پاک.
- ☐ سه بازی متوالی (سه بازی متفاوت) → هیچ نشتی state: صفحه هر بازی صفر شروع می‌شود، بدون پیام کهنه/daوری کهنه.
- ☐ rematch دو بار پشت‌سرهم توسط کلاینت → فقط یک درخواست فعال؛ دکمه «rematch requested — waiting…».
- ☐ کلاینت وسط awaiting خارج می‌شود → هاست داوری برنده می‌گیرد (ران بدون finish می‌بازد).

## ۷. KIهای تازه (درس‌های اجرای واقعی)

- **KI-48**: `tauri-plugin-single-instance` تست دو-نمونه‌ای روی یک ماشین را ناممکن می‌کند — سناریوهای LAN باید از همان ابتدا روی دو ماشین فیزیکی (یا دو حساب ویندوز جدا) برنامه بریزند؛ تست جعلی دو-نمونه‌ای ارزش سناریو را نمی‌دهد.
- **KI-49**: نام متغیر امضای آپدیتر Tauri v2 دقیقاً `TAURI_SIGNING_PRIVATE_KEY` است (نه PATH_...)؛ بیلد بدون آن NSIS را می‌سازد ولی sig نمی‌دهد و فقط در انتهای خروجی خطا می‌دهد — خروجی را تا آخر بخوانید.
- **KI-50**: الگوی انتشار gini: Release گیت‌هاب = سه فایل (exe + sig + latest.json) با endpoint `releases/latest/download/latest.json` — نسخه بعدی بدون هیچ تغییر کدی، فقط Release جدید.
